# 研究與決策：注音島

**Feature**: [spec.md](./spec.md) ・ **Plan**: [plan.md](./plan.md) ・ **Date**: 2026-11-06

> **2026-11-06 修訂**：使用者決定「遊戲資料雲端化、規則由伺服器計算、不做離線、拿掉家長區、保留訪客」。R2～R5、R7 已依此改寫：所有規則在 Go（`game-api/internal/game/`），前端只負責呈現與作答互動。

已經和使用者確認過的技術選擇記錄在 [technical-constraints.md](./technical-constraints.md)，這裡不重複。本文件處理規劃時才浮現的未知事項，每一項都寫出決策、理由與考慮過的替代方案。

## R1. 注音符號、聲調與單字的發音

**問題**：FR-022 要求能播放 37 個符號、5 種聲調示範與名稱中每個字的發音，但目前只有寶可夢整個名稱的音檔。

**Decision**：
- **以「音節」而不是「字」作為發音單位**。音檔以注音音節命名，例如「卡」播放 `ㄎㄚˇ` 的音檔。好處是：
  - 多音字自動正確，因為校對好的注音已經決定了讀音。
  - 同音字共用音檔，例如「丘」「秋」都是 `ㄑㄧㄡ`。
  - 第一世代 151 個名稱只需要約 250 個不重複的音節。實際數量由產生腳本統計。
- **符號發音依台灣注音教學的唸法**：
  - 聲母帶韻：ㄅㄆㄇㄈ 唸「ㄛ」，ㄉㄊㄋㄌㄍㄎㄏ 唸「ㄜ」，ㄐㄑㄒ 唸「ㄧ」。
  - ㄓㄔㄕㄖㄗㄘㄙ 只唸本音。
  - 韻母和介音唸本音。
- **產生方式**：沿用 `crawlers/` 裡的 Google Cloud TTS 流程，語音用 `cmn-TW` 女聲。
  - 每個音節挑一個讀音唯一的「代表字」送去合成，例如 ㄅㄛ 用「玻」、ㄎㄚˇ 用「卡」，避免 TTS 自己猜多音字。
  - 代表字對照表放在 `data/audio/syllable-chars.json`，由腳本產生初稿後人工確認。
- **聲調示範**：用「ㄇㄚ ㄇㄚˊ ㄇㄚˇ ㄇㄚˋ ˙ㄇㄚ」（媽、麻、馬、罵、嗎）五個音檔。
- **固定語句**：題目和提示的固定句子（例如「的第一個音是哪一個？」「再聽一次」「好棒！」）一句一個音檔，句子文字集中在 `data/audio/prompts.json`。
- **組合播放**：動態題目由多個片段依序播放，例如「皮卡丘」名稱音檔接上「的第一個音是哪一個？」。
- **驗收**：
  - 腳本輸出試聽清單 `data/audio/review.md`，由使用者逐一試聽。
  - 不合格的符號改成真人錄音，放進 `data/audio/overrides/`，產生時優先採用。
  - 最可能需要真人錄音的是 ㄓㄔㄕㄖㄗㄘㄙ 這幾個只唸本音、沒有韻母的符號。

**Rationale**：以音節為單位能把錄音量從「每個字」降到「每個音節」，並且直接利用已校對的注音，不會重新引入多音字錯誤。

**Alternatives considered**：
- **以字為單位**：檔案數更多，而且多音字會依 TTS 判斷而唸錯，否決。
- **SSML `<phoneme>` 指定讀音**：Google TTS 對中文 phoneme 的支援不穩定，只當作代表字合成失敗時的備案。
- **全部真人錄音**：品質最好但工作量大，只保留給 TTS 不合格的項目。

## R2. 熟練度與間隔重複演算法

**問題**：FR-033～FR-036 需要可測試、能從作答紀錄重新計算的熟練度模型，而且要符合以下驗收條件：
- 答錯的項目在接下來 5 次遭遇內至少再出現一次。
- 熟練度分 0～5 級，3 級以上算「熟悉」。

**Decision**：採用 **Leitner 盒子制**，熟練度等級就是盒子編號 0～5。

| 事件 | 新等級 | 下次複習 |
|---|---|---|
| 新項目 | 0 | 立即可出 |
| 第一次就答對 | `min(5, level + 1)` | 依新等級：L1 隔 3 次遭遇、L2 隔 1 天、L3 隔 3 天、L4 隔 7 天、L5 隔 21 天 |
| 答錯一次後答對 | 不變 | 隔 3 次遭遇 |
| 答錯兩次 | `max(0, level - 2)` | 隔 2 次遭遇 |

- **時間單位**：「隔 N 次遭遇」以該小朋友的遭遇序號計算，「隔 N 天」以作答時間計算。兩者都只依賴作答紀錄，所以結果可以重新計算。
- **選項數量**：L0～L1 給 2 個選項，L2～L3 給 3 個，L4～L5 給 4 個（FR-036）。
- **到期優先**：出題時先挑「已到期且等級最低」的項目，其次是新項目，最後是未到期的項目。
- **實作位置**：Go 套件 `internal/game/mastery`，純函式 `Apply(entry, answer) → entry`，不碰資料庫。伺服器在寫入作答的同一個交易中更新 `mastery` 表，所以兩台裝置同時玩同一個小朋友也不會互相覆蓋（以 `SELECT … FOR UPDATE` 鎖住該小朋友的列）。

**Rationale**：Leitner 規則簡單、可以完整寫成單元測試，也容易對家長解釋。SM-2 一類的演算法需要「難易度」評分，5 歲小朋友無法提供。

**Alternatives considered**：
- **SM-2 / FSRS**：需要使用者自評或大量資料調參，否決。
- **只用錯誤次數加權隨機**：無法保證「5 次遭遇內再出現」，也無法拉長複習間隔，否決。

## R3. 遭遇的寶可夢怎麼挑

**Decision**：
1. 依目前區域決定「這次要練的目標項目」：從到期清單（R2）取出優先順序最高的項目。
2. 候選寶可夢必須同時符合兩個條件：
   - 屬於目前區域。
   - 名稱能出出練到目標項目的題目，例如目標是 ㄆ 就要找名稱含 ㄆ 的寶可夢。
3. 在候選中加權隨機抽一隻：
   - 未收服的權重 ×2。
   - 稀有寶可夢的基礎權重 0.1；連續答對每多 1 題，稀有權重加 0.1，上限 0.6。連續答對中斷就歸零（FR-043）。
4. 沒有候選時，退回區域內的隨機寶可夢。
5. 每區的寶可夢名單與稀有名單放在 `data/gen1-zones.json`，由腳本依屬性產生初稿，再人工調整，確保每區的名稱能涵蓋該區所有練習項目。

**每區能練到的項目**（腳本驗證涵蓋率）：

| 區域 | 階段 | 練習項目 |
|---|---|---|
| 新手草原 | 學注音 | 21 個聲母 |
| 泡泡海灘 | 學注音 | 3 個介音、13 個韻母、5 種聲調 |
| 拼音森林 | 拼注音 | 第一世代名稱中的音節（先二拼，再三拼，最後整個名稱） |
| 文字山丘 | 認字 | 第一世代名稱中的字 |

**注意**：泡泡海灘的韻母有幾個在第一世代名稱裡可能很少見，例如 ㄝ 單獨出現的次數。
- 名稱出現次數不足的符號，改用「聽音找符號」題型練習。這個題型不需要名稱含有該符號，寶可夢只是收服的對象。
- 腳本會列出每個符號在 151 個名稱中出現的次數。

**Rationale**：讓「遇到哪隻寶可夢」直接服務學習目標（FR-035），又保留收集的驚喜。

## R4. 干擾選項

**Decision**：
- **符號混淆表**（`data/confusables.json`，人工維護）：
  - ㄅ/ㄆ/ㄉ、ㄇ/ㄋ/ㄌ、ㄍ/ㄎ/ㄏ
  - ㄓ/ㄗ、ㄔ/ㄘ、ㄕ/ㄙ、ㄐ/ㄓ/ㄗ
  - ㄢ/ㄤ、ㄣ/ㄥ、ㄛ/ㄡ、ㄟ/ㄝ
  - 二聲/三聲、一聲/四聲
- **聲調**：干擾項來自混淆表，再補隨機聲調。
- **字**：
  - 先從其他寶可夢名稱中的字裡挑，排除同音字（同一個注音）和所有能讓答案成立的字。
  - 字形相近的字放在 `data/confusables.json` 的 `chars` 區塊，之後再擴充。
- **共同規則**：所有干擾項都經過 `isAlsoCorrect(question, option)` 檢查。這個函式有獨立的單元測試，涵蓋「同音字」「多音字」「輕聲」等邊界情況。

## R5. 伺服器為準的遊戲流程與斷線處理

**問題**：使用者要求所有遊戲資料存在伺服器、規則由伺服器計算，不做離線遊玩。但小朋友每點一次選項都等網路，回饋會延遲。

**Decision**：
- **遭遇由伺服器建立**：
  - 前端送出 `POST /children/{id}/encounters { zone }`。
  - 伺服器依熟練度挑選目標項目與寶可夢，產生 1～3 題，存進 `encounters` 表後回傳。
  - 每道題目都包含顯示模型、選項、語音片段與正確答案。
- **作答在前端立即判斷**：
  - 題目已經帶有答案，所以前端的作答狀態機能立即回饋：第一次錯變淡、第二次錯標示正解。
  - 每題結束時送出 `PUT /encounters/{id}/answers/{index} { wrongCount, durationMs }`。
  - 用 `PUT` 加上固定的題號，所以重送一定只算一次（idempotent）。
  - 伺服器在同一個交易中更新熟練度與連續答對數。
- **收服由伺服器結算**：
  - 前端送出 `POST /encounters/{id}/complete`。
  - 伺服器依該遭遇的作答重新計算星星，不採信前端的星星數，並更新收服紀錄、夥伴經驗值與進化、區域開放、道館徽章。
  - 回傳「這次發生了什麼」：星星數、是否新收服、經驗值、是否進化、新開放的區域、徽章。前端依結果播放動畫。
  - 重送同一個 complete 會回傳同樣的結果。
- **預先建立下一次遭遇**：
  - 收服動畫播放時，前端先建立下一次遭遇，所以走進草叢時不必等網路。
  - 如果小朋友換了區域，就丟棄這個遭遇再建立新的。
  - 未完成的遭遇放著不處理，24 小時後由伺服器清除。
- **斷線**：
  - 前端的 API 用戶端有一個記憶體中的重送佇列，失敗時以 1、2、4、8 秒（上限 15 秒）重試。
  - 有請求在重試時，畫面顯示「連線中」的遮罩並暫停遊戲；恢復後自動繼續。
  - 重新整理頁面時，佇列中未送出的作答會遺失。佇列通常只有幾秒鐘的資料，可以接受。
- **進度讀取**：`GET /children/{id}/state` 回傳收集冊、夥伴、徽章、已開放的區域、各項目的熟練度摘要。前端只在記憶體中快取，不寫進瀏覽器儲存。
- **兩台裝置同時玩**：
  - 作答與收服都是伺服器上的交易，鎖定該小朋友的列，所以不會互相覆蓋。
  - 收服紀錄取聯集，星星取最高（`GREATEST`）。

**Rationale**：
- 規則只在 Go 寫一份，資料一定一致，符合使用者「伺服器為準」的要求。
- 題目帶答案讓點選的回饋沒有延遲；小朋友在開發者工具看答案不是需要防範的情境。
- 前端程式大幅簡化：不需要 IndexedDB、Service Worker、事件合併。

**Alternatives considered**：
- **每次點選都問伺服器對不對**：網路慢時回饋延遲，對 5 歲小朋友體驗差，否決。
- **前端計算規則，伺服器只保存**：使用者明確選擇伺服器計算，否決。
- **事件溯源加離線佇列**（原本的設計）：使用者決定不做離線，複雜度不再值得，否決。

## R6. 帳號安全

**Decision**：
- **密碼**：
  - 用 argon2id（`golang.org/x/crypto/argon2`）雜湊，參數 m=64 MiB、t=1、p=4。VPS 記憶體有限時可以調低。
  - 長度至少 8 字元，沒有其他組成規則。
- **帳號名稱**：3～20 字元，允許英數字、底線，比對時不分大小寫。
- **救援碼**：
  - 16 個字元，Crockford Base32，顯示成 `XXXX-XXXX-XXXX-XXXX`。
  - 用 argon2id 雜湊保存，用過就換新的（FR-051）。
- **Session**：
  - 32 bytes 隨機 token，資料庫只存 SHA-256。
  - Cookie 設定：`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/api`。
  - 有效 30 天，每次使用就延長（sliding）。
  - 登出或重設密碼會刪除該帳號的所有 session。
- **CSRF**：
  - `SameSite=Lax` 再加上所有寫入請求必須是 `Content-Type: application/json`。
  - 跨站表單無法送出 JSON，所以不需要另外的 CSRF token。
- **訪客（FR-058）**：
  - 按「開始」時如果沒有 session，前端呼叫 `POST /auth/guest`，伺服器建立 `is_guest = true`、沒有帳號名稱與密碼的帳號，並自動建立一個小朋友檔案（暱稱「小訓練家」、預設頭像、起始階段「學注音」）。
  - 訪客 session 有效 1 年，同樣是 sliding。
  - 在訪客 session 下註冊：直接把這個帳號補上帳號名稱、密碼、救援碼，`is_guest` 改為 false，資料完全不用搬。
  - 在訪客 session 下登入既有帳號：請求帶 `bringGuestChildren`。為 true 時，把訪客的小朋友檔案移到該帳號（超過 8 個上限就回 422）；之後刪除訪客帳號。
  - 超過 180 天沒有使用的訪客帳號，由每天的清理工作刪除。
- **登入失敗限制（FR-053）**：
  - 同一帳號連續失敗 5 次，鎖 15 分鐘。
  - 回應 `429` 並附 `Retry-After`。
  - 成功登入就歸零。
- **帳號列舉**：
  - 登入錯誤一律回「帳號或密碼不正確」。
  - 註冊時會揭露「名稱已被使用」，這是 US5 的驗收條件，可以接受。
- **管理者重設密碼（FR-052）**：
  - 透過同一個執行檔的子指令：`docker compose exec game-api game-api admin reset-password --username xxx`。
  - 指令會印出新的臨時密碼和新的救援碼。
- **註冊**：公開註冊，MVP 不做頻率限制（FR-060）。Caddy 層的請求大小上限照常設定。

## R7. 起始階段（取代家長區）

**Decision**：
- 使用者決定拿掉家長區，所以不做門檻題目、遊戲時間提醒、學習設定頁。
- 建立小朋友檔案時選擇起始階段，決定一開始開放的區域：
  - 學注音：新手草原
  - 拼注音：新手草原、泡泡海灘、拼音森林
  - 認字：全部四區
- 之後的區域依熟練度開放（FR-017）。
- 小朋友檔案的管理（新增、改名、換頭像、刪除）放在帳號頁。刪除需要再輸入密碼，避免小朋友誤刪；訪客沒有密碼，所以訪客不能刪除檔案。

## R8. 3D 場景與效能

**Decision**：
- **場景**：全部用程式產生的 low-poly 幾何，不載入 3D 模型檔。樹、石頭、草叢用 `InstancedMesh`。這和樣稿相同，首次載入的負擔最小。
- **寶可夢**：
  - 建置時把 151 張官方圖片預先處理成「貼紙」webp：256px，含白邊和墨線。
  - 執行時只是貼圖加上 billboard，不在瀏覽器端用 canvas 描邊。
  - 剪影用同一張圖加 CSS / shader 塗黑。
- **品質自動調整（FR-082）**：
  - 用 drei 的 `PerformanceMonitor`。
  - 掉格時依序：降低 DPR（最低 1）、關閉陰影、減少裝飾物件數量。
  - 手機一開始就從低品質開始。
- **減少動態效果（FR-083）**：讀取 `prefers-reduced-motion`。
  - 關閉鏡頭推拉動畫和彈跳。
  - 草叢改成靜態高亮。
  - 收服改成淡入淡出。
- **畫面分層**：
  - 3D 只放在 `<Canvas>` 裡，挑戰面板、收集冊、帳號頁都是 2D DOM。
  - 這樣按鈕大小、對比、鍵盤操作、螢幕閱讀器都可以用一般的網頁方式處理（憲章六）。
- **測試掛勾**：
  - 測試建置（`NEXT_PUBLIC_E2E=1`）時，在 `window.__zhuyinIsland` 掛上：
    - `enterGrass()`：直接觸發遭遇
    - `setZone(zone)`：把玩家移到某一區
    - `getState()`：讀取目前的 store
  - 伺服器在 `GAME_API_TEST_HOOKS=1` 時接受 `X-Test-Pokemon` 標頭，指定遭遇的寶可夢；正式環境關閉。
  - Playwright 不需要在 canvas 上點擊就能測完整流程。

## R9. 首次載入與字型

**問題**：SC-003 要求首次載入 10 秒內可以開始玩，憲章五要求 FCP 1.5 秒、LCP 2.5 秒。

**Decision**：
- **首屏**：首屏是純 HTML 的「開始」畫面，含大按鈕，Edge Case 要求要先點擊才能播放聲音。這個畫面用來量 FCP 和 LCP，3D 場景與音檔在背景載入。
- **字型子集化**：
  - 建置時用 `subset-font`（harfbuzz wasm）把粉圓切成只含需要的字，輸出 woff2。需要的字包括：
    - 介面文字
    - 151 個名稱
    - 干擾字
    - 注音符號
  - 預估從 4.9 MB 降到 200 KB 以下。
  - 字型檔放在 `public/fonts/`，不再從 jsDelivr 載入。
- **音檔載入順序**：
  - 優先：目前區域會用到的音檔。
  - 其餘在閒置時預先載入。
  - 全部音檔約 151×2 個名稱、約 250 個音節、37 個符號、約 60 句提示，用 64 kbps mp3 估計約 10 MB。
- **寶可夢貼紙**：151 張 256px webp，估計約 3 MB，依區域分批載入。
- **Three.js**：`three` + R3F + drei 只引入需要的模組，3D chunk 目標 gzip 後低於 250 KB。

**Rationale**：讓「看得到、按得到開始」和「3D 全部就緒」分開計算，兩個指標都能達成。

## R10. 部署與靜態輸出

**Decision**：
- **前端**：
  - 維持 `output: 'export'`。
  - `basePath` 改由環境變數控制：GitHub Pages 用 `/pokedex-for-kids`，VPS 用空字串。
  - `images.unoptimized: true`，靜態輸出無法使用 Next 的圖片最佳化伺服器，圖片改在建置時預先處理（R8）。
- **Caddy**：
  - `/api/*` 反向代理到 `game-api:8080`，其餘提供 `out/` 靜態檔。
  - 自動取得 HTTPS 憑證。
  - 靜態資源帶 hash 的檔案長期快取，HTML 不快取。
- **本機開發**：
  - `docker compose up` 啟動 `postgres` 和 `game-api`。
  - 前端用 `next dev`，在 `next.config.js` 裡設定 rewrites，把 `/api` 轉到 `localhost:8080`。
  - 同源的 cookie 行為和正式環境一致。
  - Next 的 rewrites 只在 dev 有效，靜態輸出不受影響。
- **Go 版本**：pgx 與 goose 的新版要求 Go 1.26，本機的舊版 Go 會自動下載 toolchain；Docker 映像用 `golang:1.26-alpine` 建置、`gcr.io/distroless/static` 執行。
- **本機埠號**：開發機的 8080、5432 已被其他服務占用，所以 compose.dev 對外開 18080（API）與 55432（Postgres）。
